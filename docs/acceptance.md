# MVP 受け入れ確認（仕様書 §12）

Supabase に接続したあと、A-01〜A-10 を通すための手順。

DB の挙動で決まるもの（A-01 / A-07 / A-09 / A-10）は自動化してある。
画面の操作で確かめるもの（A-02〜A-06 / A-08）は手で追う。

---

## 0. 準備

### Supabase プロジェクトを作る

1. [supabase.com](https://supabase.com) でプロジェクトを作成（無料枠で可）
2. **Project Settings → API** から次を控える
   - Project URL
   - `anon` `public` キー
   - `service_role` キー（**秘密**。クライアントに出さない）

### 環境変数

```bash
cp .env.example .env.local
```

`.env.local` に上の3つと `NEXT_PUBLIC_SITE_URL=http://localhost:3000` を入れる。
Stripe は未設定で構わない（Pro ページが「準備中」になるだけ）。

### マイグレーションを適用する

Supabase ダッシュボードの **SQL Editor** で、次の順に実行する。

1. `supabase/migrations/0001_init.sql`
2. `supabase/migrations/0002_study_session_pause.sql`

### 認証設定

**Authentication → URL Configuration** の Redirect URLs に
`http://localhost:3000/auth/confirm` を追加する。

ローカルで確認メールを踏むのが面倒なら、
**Authentication → Providers → Email** の「Confirm email」を一時的に切ると
登録直後にログイン状態になる。**本番では必ず戻すこと。**

## 1. 自動で確認する（A-01 / A-07 / A-09 / A-10）

```bash
npm run verify:db
```

検証専用のユーザーを2つ作り、最後に必ず削除する。既存データには触れない。

| 確認項目 | 対応する条件 |
| --- | --- |
| 登録時に profiles / notification_settings / subscriptions が作られる | A-01 |
| 0002 の列（`segment_started_at` / `accumulated_sec`）が存在する | — |
| 実行中のタイマーがユーザーごとに1件までに制限される | — |
| 他人のデータが SELECT / UPDATE / DELETE できない | A-09 |
| 他人の `user_id` で INSERT できない | A-09 |
| 未ログインでは何も読めない | A-09 |
| 本人でも `entitlement` を書き換えられない | A-07 |
| `service_role` からは更新できる（Webhook 経路） | A-07 |
| アカウント削除で全テーブルから消える | A-10 |
| 無関係のユーザーは消えない | A-10 |

全部 PASS すれば、この4つは満たしている。

## 2. 画面で確認する

```bash
npm run dev
```

**モバイル幅（390px）で確認すること**（§14.1）。
ブラウザの開発者ツールでデバイスを iPhone 14 などに切り替える。

### A-01 登録・ログイン・ログアウト

1. `/` →「無料で始める」→ メールとパスワードで登録
2. オンボーディングで表示名と学校種別を入れる → ホームへ着く
3. その他 → 設定 → ログアウト → `/login` に戻る
4. 同じメールでログインし直せる
5. `/login` で「パスワードを忘れた場合」→ 再設定メールが届く

### A-02 時間割

1. その他 → 科目 → 科目を1つ追加（色も選ぶ）
2. 時間割 → 曜日を選ぶ →「○曜日に授業を追加」
3. 時限を変えると開始/終了時刻が入れ替わることを確認
4. **同じ曜日・同じ時限をもう一度選ぶと警告が出て、それでも保存できる**（§5.1）
5. 保存後、その曜日の一覧に出る
6. 授業をタップ → 編集して保存 → 反映される
7. 授業をタップ → 削除できる
8. **ホームに「次の授業」が出る**。今が授業時間中なら「今の授業／進行中」になる

### A-03 課題

1. 下部ナビの ＋ →「課題を追加」
2. タイトル・科目・締切（日付のみ／日時の両方を試す）・優先度・状態を入れて保存
3. **一覧が締切順に並ぶ**
4. 期限切れは赤、今日は琥珀色のバッジになる
5. チェックボックスで完了 → 完了済みタブに移る → 戻せる
6. 編集画面から削除できる
7. 科目チップで絞り込める
8. ホームに「締切が近い課題」が最大3件出る

### A-04 Todo

1. Todo 画面（その他 → Todo）で1行入力して追加
2. 期限を入れたものと入れないものを両方作る
3. チェックで完了 → 完了済みタブに移る
4. × で削除できる
5. 今日／今週のタブで振り分けが変わる
6. ホームの「今日のTodo」から直接追加・完了できる

### A-05 タイマー

1. タイマー → 科目を選んで開始
2. 秒が進む
3. 一時停止 → **秒が止まる**
4. **ブラウザのタブを閉じて開き直す** → 一時停止のまま、経過も保たれている
5. 再開 → 続きから進む
6. 終了して記録 → 「◯分を記録しました」と出る
7. その他 → 分析 → 履歴に**停止していた時間を含まない**実勉強時間が載る
8. ホームの「今日の勉強時間」「今週の合計」に反映される

### A-06 Free 上限

課題20件・Todo30件を手で作るのは大変なので、SQL Editor でまとめて入れる。
`<自分のuser_id>` は `select id from auth.users where email = '自分のメール';` で調べる。

```sql
insert into public.assignments (user_id, title, due_at)
select '<自分のuser_id>', '上限テスト' || n, now() + interval '3 day'
from generate_series(1, 20) as n;
```

1. 課題画面を開く → 「未完了 20件 / 20件まで」と出る
2. **「課題を追加」ボタンが消え、Pro 案内が出る**
3. `/assignments/new` を直接開いても一覧に戻される
4. 1件を完了にすると、また追加できるようになる
5. Todo も同様（30件で試す）

後片付け：

```sql
delete from public.assignments where title like '上限テスト%';
```

### A-08 モバイル幅

390px で次の画面を開き、**横スクロールが出ないこと**を確認する。

- ホーム / 時間割 / 課題 / Todo / タイマー / 分析 / その他 / 設定 / Pro
- 課題の追加フォーム、授業の追加フォーム
- 下部ナビが隠れず、＋ を押すとシートが出る

### A-10 アカウント削除（画面から）

自動検証で DB の連鎖削除は確認済みだが、画面の導線も一度通す。

1. **確認用に捨てアカウントを新規登録する**（本番で使うアカウントでは試さない）
2. 設定 → アカウントを削除する
3. 確認欄に「削除」と入力 → 完全に削除
4. トップページに戻り、同じメールでログインできなくなる

## 3. Stripe まで通す場合（A-07 の課金側）

Supabase だけで A-01〜A-10 は通る。課金まで確かめるときは README の
「Stripe を設定する」に従ってから、テストモードで次を確認する。

1. Pro ページ → プランを選ぶ →「Proにする」
2. Stripe のテストカード `4242 4242 4242 4242` で決済
3. 戻ってきた直後に **Pro になっている**（§10.2 手順6）
4. 課題の上限が外れ、分析に科目別が出る
5. 「支払い方法・解約の管理」→ Stripe のポータルが開く
6. ポータルで解約 → アプリに戻ると Free に戻っている
